01 — Visão Geral

O que é um seguidor de linha?

Um robô seguidor de linha é um sistema autônomo capaz de detectar e percorrer uma trajetória marcada no chão — geralmente uma faixa preta sobre fundo branco — sem intervenção humana. É o "Olá Mundo" da robótica autônoma: simples o suficiente para aprender em dias, mas complexo o suficiente para ensinar os fundamentos reais do trabalho em equipe de engenharia.

Neste projeto guiado, a proposta é projetar, simular e documentar um seguidor de linha em grupo, cobrindo quatro frentes: Gestão, Mecânica, Eletrônica e Programação. Este artigo vai destrinchar cada uma delas.

✅ Boa notícia

A entrega física não é obrigatória. Simulações em Tinkercad, Webots, Fusion 360 ou qualquer software são totalmente aceitas. Foque na qualidade do relatório.

Como o robô "enxerga" a linha?

A magia toda está no sensor infravermelho (IR). Ele emite luz IR e mede o quanto é refletido de volta: superfície branca reflete muito (sinal alto), superfície preta absorve quase tudo (sinal baixo). Com dois ou mais sensores posicionados embaixo do chassi, o Arduino consegue saber se o robô está sobre a linha, saindo pela esquerda ou saindo pela direita.

1
Sensor lê a pista
Os sensores IR apontam para o chão e retornam valores digitais (0 ou 1) indicando se estão sobre linha preta ou fundo branco.
2
Arduino processa
O microcontrolador lê os pinos de entrada, compara os estados dos sensores e calcula o erro de posição em relação à linha.
3
Motores corrigem
Via Ponte H (L298N), o Arduino ajusta a velocidade de cada motor para curvar o robô de volta à linha.

Por que usar Ponte H (L298N)?

Motores DC consomem corrente demais para serem ligados diretamente nos pinos do Arduino (com corrente recomendada de 20 mA por pino no Uno R3). A Ponte H é um circuito de potência que deixa o Arduino controlar sem alimentar diretamente os motores. Ela também permite inverter o sentido de rotação (necessário para curvas e ré).

O controle de velocidade é feito via PWM (Pulse Width Modulation): o Arduino "pulsa" o sinal em alta frequência e a variação da largura do pulso define a velocidade média do motor.

Alimentação e jumpers

Não alimente Vin com 5 V: a entrada passa por um regulador. Para a bancada, alimente o Arduino por USB e os motores por uma fonte dimensionada, mantendo GND comum. Confira a documentação do seu módulo L298N antes de usar o regulador integrado e retire os jumpers ENA/ENB se for controlar esses pinos por PWM. Verifique a queda de tensão da ponte e a corrente de partida dos motores.

Consulte a documentação oficial do Arduino Uno R3 e o datasheet do L298 para dimensionar as conexões.

04 — Estrutura e Mecânica

Chassi e posicionamento

O chassi é a espinha dorsal do robô. Para o Desafio, você pode projetar em Fusion 360, Tinkercad 3D, ou até desenhar à mão com cotações. O importante é que o projeto seja justificado.

Configuração de acionamento: diferencial

A configuração mais simples — e recomendada — é a acionamento diferencial: dois motores nas laterais traseiras + uma roda boba na frente. Para virar, basta aplicar velocidades diferentes nos dois motores.

📐 Altura dos sensores

Mantenha os sensores IR entre 3mm e 10mm do chão. Muito alto → leitura imprecisa. Muito baixo → pode raspar na pista. Sensor na linha central entre as rodas funciona bem como ponto de partida.

Material do chassi

A
Acrílico cortado a laser
Profissional, leve e fácil de furar. Precisa de acesso a uma cortadora. Excelente para portfólio.
B
MDF (6mm)
Barato, fácil de trabalhar com ferramentas básicas. Pode ser cortado com estilete e furadeira. Boa opção para prototipagem.
C
Impressão 3D (PLA)
Máxima liberdade geométrica. Se o grupo tem acesso a impressora 3D, é a melhor escolha para demonstrar habilidade em CAD.
05 — Programação

Lógica e código C/C++

O código é o coração do robô. Vamos do mais simples ao mais sofisticado, para vocês escolherem o nível certo para o relatório.

Nível 1: Controle Bang-Bang (Liga/Desliga)

A abordagem mais direta: se o sensor esquerdo detectar linha, vira à esquerda; se for o direito, vira à direita. Funciona, mas causa um movimento ziguezagueante.

Geometria deste exemplo

Os sensores devem ficar próximos o suficiente para que ambos detectem a faixa quando o robô estiver centralizado. Se sua montagem coloca um sensor de cada lado de uma linha estreita, a tabela de estados muda. Confira cada estado com as rodas suspensas antes de colocar o robô na pista.

C/C++ — Arduino seguidor_bangbang.ino 
// Dois sensores DIGITAIS: LOW sobre a linha, HIGH no fundo.
// Verifique a polaridade do seu módulo antes de usar.
const int SENSOR_ESQ = A0, SENSOR_DIR = A1;
const int ENA = 5, IN1 = 6, IN2 = 7;
const int ENB = 10, IN3 = 8, IN4 = 9;
const int VEL_BASE = 120;

void moverMotores(int esquerda, int direita) {
  digitalWrite(IN1, HIGH); digitalWrite(IN2, LOW);
  digitalWrite(IN3, HIGH); digitalWrite(IN4, LOW);
  analogWrite(ENA, constrain(esquerda, 0, 255));
  analogWrite(ENB, constrain(direita, 0, 255));
}

void setup() {
  pinMode(SENSOR_ESQ, INPUT); pinMode(SENSOR_DIR, INPUT);
  pinMode(ENA, OUTPUT); pinMode(ENB, OUTPUT);
  pinMode(IN1, OUTPUT); pinMode(IN2, OUTPUT);
  pinMode(IN3, OUTPUT); pinMode(IN4, OUTPUT);
  moverMotores(0, 0);
}

void loop() {
  bool esquerdaNaLinha = digitalRead(SENSOR_ESQ) == LOW;
  bool direitaNaLinha = digitalRead(SENSOR_DIR) == LOW;
  if (esquerdaNaLinha && direitaNaLinha)
    moverMotores(VEL_BASE, VEL_BASE);
  else if (esquerdaNaLinha)
    moverMotores(VEL_BASE / 2, VEL_BASE);
  else if (direitaNaLinha)
    moverMotores(VEL_BASE, VEL_BASE / 2);
  else
    moverMotores(0, 0); // Perdeu a linha: pare e reposicione.
}

Nível 2: Controle Proporcional (P)

Usando sensores analógicos em vez de digitais, conseguimos calcular um erro contínuo e corrigir os motores proporcionalmente — o robô curvará suave quando estiver levemente desviado e bruscamente quando estiver muito fora.

C/C++ — Arduino seguidor_proporcional.ino 
// Exemplo completo com SAÍDAS ANALÓGICAS dos sensores em A0/A1.
// Hipótese: leitura maior na linha preta e menor no fundo branco.
const int SENSOR_ESQ = A0, SENSOR_DIR = A1;
const int ENA = 5, IN1 = 6, IN2 = 7;
const int ENB = 10, IN3 = 8, IN4 = 9;
const int VEL_BASE = 100;
const float Kp = 0.15;
// Exemplo inicial: substitua pelo limiar medido em seu piso.
const int LIMIAR_LINHA = 500;

void moverMotores(int esquerda, int direita) {
  digitalWrite(IN1, HIGH); digitalWrite(IN2, LOW);
  digitalWrite(IN3, HIGH); digitalWrite(IN4, LOW);
  analogWrite(ENA, constrain(esquerda, 0, 255));
  analogWrite(ENB, constrain(direita, 0, 255));
}

void setup() {
  pinMode(ENA, OUTPUT); pinMode(ENB, OUTPUT);
  pinMode(IN1, OUTPUT); pinMode(IN2, OUTPUT);
  pinMode(IN3, OUTPUT); pinMode(IN4, OUTPUT);
  Serial.begin(9600);
  moverMotores(0, 0);
}

void loop() {
  int esquerda = analogRead(SENSOR_ESQ);
  int direita = analogRead(SENSOR_DIR);
  if (esquerda < LIMIAR_LINHA && direita < LIMIAR_LINHA) {
    moverMotores(0, 0);
    return;
  }
  // Linha mais à direita: aumente o motor esquerdo para virar à direita.
  int erro = direita - esquerda;
  int correcao = (int)(Kp * erro);
  moverMotores(VEL_BASE + correcao, VEL_BASE - correcao);
  Serial.println(erro);
  delay(10);
}

Meça cada sensor sobre o fundo e a faixa; compense diferenças entre eles. Se a polaridade for invertida, adapte a leitura e a condição de perda de linha. Comece com velocidade e ganho baixos, observe o sinal do erro e aumente o ganho gradualmente. Este controle P não estima uma posição absoluta e não trata cruzamentos.

06 — Gestão do Projeto

Organização e cronograma

Uma divisão em quatro etapas ajuda a organizar o trabalho. Ajuste a duração de cada etapa aos recursos do grupo e reserve tempo para testar o conjunto.

Sugestão de divisão de tarefas

D1
Planejamento e divisão
Definir quem faz cada frente (Gestão, Mecânica, Eletrônica, Programação). Abrir o documento do relatório com a estrutura já montada. Cada responsável começa sua seção.
D2
Desenvolvimento
Mecânica: CAD do chassi. Eletrônica: esquemático no Tinkercad. Programação: escrever e comentar o código. Gestão: lista de materiais + cronograma detalhado.
D3
Integração e simulação
Juntar todas as partes no relatório. Rodar simulações e capturar prints/gifs. Revisar o texto e verificar se todos os objetivos do projeto estão cobertos.
D4
Revisão final e apresentação
Revisar formatação, capa com nomes/RA, exportar PDF. Revise com o grupo antes de apresentar.
07 — Relatório Técnico

Como estruturar o documento

O relatório registra as decisões e permite repetir os testes. Use a estrutura abaixo como sugestão; requisitos de processos seletivos devem ser consultados no edital vigente.

✓
Capa
Nome completo e RA de todos os integrantes, título do projeto, data. Inclua também a versão do documento.
✓
Introdução
O que é um seguidor de linha? Como funciona o sensor IR? Qual a aplicação real desse tipo de robô? Cite exemplos industriais (AGVs em fábricas, por exemplo).
✓
Desenvolvimento
Esquema eletrônico (print do Tinkercad), concepção mecânica (render/foto do CAD), lista de materiais com custos, dificuldades encontradas e como foram resolvidas.
✓
Conclusão
Código comentado completo, prints/gifs da simulação funcionando, propostas de melhoria.

Dicas de escrita técnica

✅ Faça

Explique o porquê de cada decisão. "Escolhemos o L298N pois suporta até 2A por canal, suficiente para os motores."

❌ Evite

Descrições genéricas sem justificativa. "Usamos o L298N porque é um componente comum."
